Evolutionary Algorithm Benchmark Selection System

Describe your optimisation problem in plain words. The system finds the closest benchmark problem in a knowledge base mined from conference papers, tells you how sure it is, and lists the evolutionary strategies that were reported on it.

Objectives

What the project sets out to do

Build the knowledge base

Turn results scattered across paper PDFs into one searchable table of benchmark problems, landscapes, algorithms and reported outcomes.

Match a problem to a benchmark

Take a user's plain-language description and find the closest known problem, instead of asking for exact function names.

Rank strategies by evidence

For each problem, list the strategies reported on it, grouped by performance metric and ordered by how much evidence supports them.

Be honest about confidence

Report how sure the match is separately from how many papers back the answer, and decline to answer when the match is weak.

Grow beyond text

Add matching on the measured shape of the user's objective function (landscape analysis), run the recommended strategies, and put it all behind a simple interface.

Problem statement

Choosing an evolutionary algorithm is still mostly guesswork

Hundreds of papers report how evolutionary algorithms perform on benchmark problems. Someone with a new problem has to read many of them, work out which benchmark resembles their own, and guess which results transfer.

The evidence exists, but it is locked in PDFs written in different styles. This project reads it once, structures it, and makes it queryable, so the question "what has worked on problems like mine?" gets an answer with its supporting evidence attached.

  • Same problem, different words.One benchmark appears under many names and spellings, so papers cannot be grouped by title alone.
  • Metrics do not compare.A mean error and a success rate cannot be ranked against each other, so strategies are ranked per metric only.
  • Missing details.Many papers leave out parameters such as population size; where we fill in a standard default, it is treated as a default, not as a finding.
Methodology

From a paper PDF to a ranked recommendation

The pipeline runs in eight stages. Each stage writes a file the next one reads, so every result can be traced back to the papers behind it.

  1. 1

    Extract LLM + fixed schema

    A language model reads each paper and fills a fixed set of fields: problem, landscape traits, algorithm, parameters, performance metric and outcome.

  2. 2

    Clean Python · Pandas

    Placeholders are standardised, duplicate records removed, and unreported numeric parameters set to standard defaults that stay marked as defaults.

  3. 3

    Describe each record

    One matching text is built per record: function name and landscape for benchmark papers, problem context and title for applied papers. Non-English text is translated.

  4. 4

    Embed all-mpnet-base-v2

    Each text becomes a 768-number sentence embedding, so descriptions with similar meaning sit close together.

  5. 5

    Group into problem entities name keys + clustering

    Records that describe the same problem are merged, using name rules (for example every CEC 2017 variant) plus embedding clusters. Entities are typed as suite, single function or named subset. Checked against a hand-labelled set of 38 papers.

  6. 6

    Rank strategies

    For each entity, strategies are ranked within each metric family, never across metrics, ordered by whether the optimum was found, how often, and how many papers report it.

  7. 7

    Match a user's query BM25 + dense + cross-encoder

    Keyword search and embedding search each return candidates; reciprocal rank fusion merges them; a cross-encoder re-scores the shortlist, with a small bonus for entities backed by more papers.

  8. 8

    Answer with confidence

    The output gives the matched entity, a match confidence (the margin between the top two candidates), the evidence strength (papers behind it) and the strategies by metric. If the margin is too small, the query is logged as unmapped.
